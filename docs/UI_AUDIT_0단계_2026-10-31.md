# 화면 완성도 0단계 점검 (2026-10-31)

목표: 화면 완성도 72점 → 90점 이상. 이 문서는 현재 상태의 기준선이며, 이후 단계가 끝날 때마다 같은 방법으로 다시 재서 비교한다.

## 점검 방법
- 개발서버에서 18개 화면을 **1440 / 1024 / 768 / 390px** 네 폭으로 열어 자동 측정(화면 안에 숨긴 iframe + 측정 스크립트).
- 측정 항목: 가로 넘침, 본문 12px 미만 글자, 누르는 곳 40px 미만, 글자 대비(WCAG AA 4.5:1 / 큰 글자 3:1), 글자 잘림, 로딩 문구, 이미지 alt.
- 공통 틀(사이드바·헤더·하단 탭·챗봇)은 화면 본문과 따로 집계했다.
- 한계: 로컬에는 Supabase 키가 없어 `/failure`·`/manual` 조회 화면은 "보관함이 설정되지 않았습니다" 상태라 측정하지 못했다. 팝업·첫 접속 화면은 자동 측정하지 않았다(눈으로 확인 필요).

## 가장 큰 발견 — 레이아웃 버그 (화면 완성도 이전의 문제)
**PC 폭 768~1280px에서 본문이 사이드바 옆 공간보다 넓어져 오른쪽이 잘린다.**
- 영향: 헤더 오른쪽의 지사·부서 칩, 홈 버튼, "깨끗한 에너지로" 배너가 화면 밖으로 밀려 보이지 않는다. 표가 넓은 화면(작업 관리, 오버홀 수량산출, 설비별 전체 현황, 현황 조회, 운영부 홈)에서 발생. 설비별 전체 현황은 1440px에서도 발생.
- 원인: `Shell.tsx`의 `<main>`이 flex 항목이라 안쪽 표의 최소 너비 아래로 줄어들지 못한다(`min-width: auto`).
- 해결: `<main>`에 `min-w-0` 한 줄. 시험으로 적용하자 위 5개 화면 모두 헤더가 화면 안에 들어왔다(배너 오른쪽 끝 1214→990 @1024px).

## 공통 틀(모든 화면)에서 나온 것
- 사이드바 하위 메뉴 펼침 화살표 32×32, 메뉴 숨기기 36×36.
- 챗봇 패널의 최소화·닫기 32×32, 추천 질문 칩 높이 30~32px.
- 폰·PC 모두 헤더 칩 위치가 화면 폭에 따라 밀림(위 레이아웃 버그).

## 단계별 반영 계획과 이 점검의 연결
| 단계 | 항목 | 이 점검에서 닫을 대상 |
|---|---|---|
| 0.5 | `<main min-w-0>` 한 줄 | 가로 넘침 5화면 + 헤더 잘림 |
| 1 | 팝업·상태 칩·화면 머리글 통일 | 칩 색 대비(진행중 2.2:1, 분야 1.64:1), 머리글 크기 불일치 |
| 2 | 로딩·빈 화면·오류 표준화, 글자 12px·터치 40px | 11px 이하 글자, 24px 이하 버튼(약 200곳) |
| 3 | 접근성·반응형·남은 화면 | 대비 미달(공정표 153), 지도 핀, 화면 제목과 탭 이름 불일치 |

## 합격 기준(재측정으로 확인)
- 어느 폭에서도 가로 넘침 0, 헤더 잘림 0.
- 본문 12px 미만 글자 0(공정표 날짜 눈금 포함).
- 누르는 요소 40px 이상(지도 핀 포함).
- 글자 대비 AA 미달 0(상태 칩 포함).
- 팝업 구현·상태 칩 구현·화면 머리글 구현이 각각 한 곳.

## 0.5단계 결과 (같은 날)
- `Shell.tsx` `<main>`에 `min-w-0` 추가 → 768~1280px에서 헤더 오른쪽(지사·부서 칩, 홈 버튼, 배너)이 잘리던 문제 해결.
- 고치고 나니 숨어 있던 문제 하나가 드러났다: **설비별 전체 현황**의 필터 줄이 한 줄로 고정돼 1024~1440px에서 오른쪽 컨트롤이 잘렸다(예전에는 본문 전체가 넓어져 가려져 있었음). `MaintenanceMatrix.tsx`의 필터 줄이 폭이 모자라면 줄을 바꾸도록 수정.
- 재측정: 15개 화면(+운영부 홈) × 1440/1280/1024/768/390px에서 헤더 잘림 0, 가로 스크롤 영역 밖으로 넘치는 내용 0.
